\section{Introduction}
\label{sec:intro}

\PARstart{L}{arge} language models (LLMs) are moving from demonstrations to deployed graders in computer science
(CS) courses. Rubric-conditioned LLMs approach human raters on well-specified short-answer tasks and return
criterion-level feedback at a scale no teaching team can match~\cite{sessler_canai_2025,henkel_roars_2025}, but
grading errors distort how students revise their work~\cite{li_am_2023}, repeated scoring of the same answer is
unstable~\cite{pack_large_2024,moazzez_assessing_2024}, and agreement with teachers varies sharply between models
and prompts~\cite{tate_can_2024}. An instructor who adopts an
LLM grader therefore makes several decisions at once: whether the model should reason before scoring,
what evaluation guidance to place in the prompt and how the model should apply it, whether to grade a
whole exam in one call or question by question, whether to score a rubric criterion by criterion or
holistically, as one overall grade, and which model to run or pay for.

The literature answers these questions only in fragments. Reasoning is the clearest example. A reasoning model
writes out its thinking before it answers, which improves the accuracy of LLMs used as judges of other models'
outputs (LLM-as-a-judge)~\cite{jayarao_explicit_2025}, but the effect depends on the task and the
architecture~\cite{larionov_deepseek_2025}, and the written-out thinking carries verbose, redundant
computation~\cite{sui_stop_2025}. In essay scoring, two reasoning models agreed less with expert raters, and less
consistently, than a model without reasoning~\cite{yoshida_reasoning_2025}, but that comparison sets different
models against each other. Models have been compared as graders of programming
assignments~\cite{jukiewicz_comparison_2026} and of bioinformatics assignments~\cite{policar_automated_2025},
and evaluation guidance has been studied for code grading~\cite{pathak_rubric_2025}, but, to our knowledge, no
study compares guidance, the prompt that tells the model how to apply it, grading scope, rubric decomposition,
and conversation state under one protocol. What is missing is an empirical answer to the instructor's question:
for a given CS assessment task, which configuration should be used, and what does it cost?

This paper studies these configuration choices under one protocol and turns the results into a
configuration guide. We vary reasoning (on or off), evaluation guidance (none versus a rubric or a
reference answer), grading scope (a whole exam in one call versus one question per call), rubric
decomposition (one holistic score versus a score per criterion), conversation state (a clean
conversation per answer versus a shared history), and the model. In the first results, some models
scored many partially correct code answers as zero, which we call zero-collapse. To address it, a follow-up
experiment tests whether the prompt alone can prevent it: first by asking the model for partial credit instead
of strict grading, and then by prompt engineering, writing prompts aimed at the reasons the models gave for
their zeros. Five models take part in our study: three open-weight models (Qwen3.5-35B-A3B, DeepSeek-V4-Flash,
GLM-5.1) and two closed ones (GPT-5.1, Claude Sonnet 4.6); the first four are graded with
reasoning both off and on within the same model, which separates the effect of reasoning from that of the model.
The study runs on four datasets in two domains. Three are public: the Mohler corpus of computer-science short
answers~\cite{mohler_text_2009,mohler_learning_2011}, the SemEval-2013 Task~7 corpus of science short
answers~\cite{dzikovska_semeval_2013}, and the Rubric Is All You Need (RIAYN) corpus of rubric-graded Java
code~\cite{pathak_rubric_2025}. The fourth, PT-CS, holds teacher-graded Java code and short answers in Portuguese
from complete exams of a course at our institution, and is the only one on which grading a whole exam in one
call and the conversation state can be studied. Two further public datasets are used only to validate the
configuration guide: SAF~\cite{filighera_saf_2022}, with short answers on communication networks, and
HARMOGEN-R~\cite{mendonca_harmogenr_2026}, with C++ code in Portuguese.

Five research questions structure the study:
\begin{itemize}
  \item \textbf{RQ1.} How does reasoning affect grading quality, consistency, and cost, and does the
        effect differ between code and short answers?
  \item \textbf{RQ2.} How much does evaluation guidance (none versus a rubric or reference answer)
        change quality and consistency?
  \item \textbf{RQ3.} How do grading scope (whole exam versus question by question) and rubric
        decomposition (holistic versus criterion by criterion) affect agreement with the final
        grade?
  \item \textbf{RQ4.} How do models available in mid-2026 compare as graders, and what is the
        cost-quality trade-off between open-weight and closed models?
  \item \textbf{RQ5.} Does conversation state (clean versus shared history) affect the grades, and does the
        order in which answers are graded change them?
\end{itemize}
These five questions were set before the experiments. The follow-up experiment was added once the
zero-collapse appeared, so it is reported after the previous experiments. It asks whether a request for partial credit changes
agreement and cost, why the models score partially correct answers as zero, and whether a prompt aimed
at that cause removes the zero-collapse without reasoning.

From these comparisons we build a configuration guide: one recommended configuration for LLM grading in CS,
which leaves the choice of model open. The \emph{tests} compare
the guide, for each model, with the baseline configuration, from which every comparison starts, and with the same
baseline with reasoning on, on the four datasets it was built from. The \emph{validation} repeats these comparisons on SAF and HARMOGEN-R, with a
criterion fixed before they were graded.

The main contribution of this paper is the configuration guide, tested on five models and validated on two
datasets that played no part in building it. Three further contributions support it. The first is the effect of each configuration choice for grading in CS (reasoning,
evaluation guidance, the prompt, grading scope, rubric decomposition, and conversation state),
isolated within the same model and measured jointly on agreement, consistency, and cost. The second is a
diagnosis of the zero-collapse, from the justifications the models wrote for their zeros, and a prompt for code,
developed by prompt engineering and aimed at its cause. The third is evidence from 97 complete computer-science exams in Portuguese, with 379 manually graded answers, which repeats every
comparison outside the public corpora and alone supports the comparisons that need complete exams.

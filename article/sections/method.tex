\section{Study Design and Method}
\label{sec:method}

We graded the answers of four datasets with five LLMs under one protocol and compared every grade with the
human grade. Each comparison changes one
configuration choice from a baseline configuration and keeps everything else fixed. Unless stated otherwise, each answer
is graded $k=5$ times in every configuration it enters, so agreement with the human graders, consistency across
the repetitions, and cost are measured together.

\emph{Reasoning} switches the model's
thinking mode off or on. The question and the student answer are always sent, and \emph{evaluation guidance} is
the grading material added to them: nothing, or the rubric (the scoring criteria) or reference answer that the
dataset provides. The \emph{prompt} tells the model how to apply that guidance. The \emph{strict prompt}, used
in the baseline, tells it to grade strictly, awarding and deducting marks exactly as the rubric specifies, or to
judge the student answer against the reference; it does not mention partial credit. The \emph{partial-credit
prompt} tells it instead to give marks for every rubric item, or part of the reference answer, that the student
answer meets, even when that answer is incomplete or its code would not compile, and to give zero only when
nothing earns marks. A third, the \emph{code prompt}, came out of a follow-up experiment on the prompt, added
because the first results showed some models scoring many partially correct code answers as zero; it is
described with that experiment below.


\emph{Scope} contrasts grading a whole multi-question exam in one call against one call per question.
\emph{Decomposition} contrasts one holistic score (a single overall grade) with a score for each rubric criterion
followed by the total; the grade is the model's total, because some rubrics describe alternative solutions and
only the criteria of the student's solution should count. \emph{Conversation state}, studied in a separate
sub-study, contrasts a clean conversation per answer with one conversation that accumulates the grading of a
student's exam; each exam is graded in its own question order and in reverse, to isolate the effect of an
answer's position. The last choice is the \emph{model}.


The \emph{baseline configuration} is reasoning off, with guidance, the strict prompt, one question per call,
holistic scoring, and a clean conversation per answer. Each comparison changes one choice from it, so every
comparison of the five research questions, the conversation sub-study included, uses the strict prompt.
Qwen3.5, DeepSeek-V4-Flash, GLM-5.1, and GPT-5.1 grade every dataset with reasoning both off and on, and each
other choice was compared on at least three of the five models; the legend of Table~\ref{tab:design} gives the
reason for every combination not compared.

Scope and conversation state need complete multi-question exams, which only PT-CS has, and decomposition needs
rubrics with separately scored criteria, which PT-CS and RIAYN have. Guidance is a question-specific rubric for
PT-CS and RIAYN and a reference answer for Mohler and SemEval, so the two are reported separately; PT-CS has no
reference solutions, and we wrote none.

\subsection{Datasets and Human Grades}
\label{sec:datasets}

Table~\ref{tab:datasets} summarises the four datasets. The \emph{human grade} is the grade a model's score is
compared against. PT-CS holds code and short answers, which we analyse separately, so per-dataset results cover
five sets: Mohler, SemEval, RIAYN, PT-CS code, and PT-CS short answers.

\input{tables/tab_datasets}

\emph{Mohler}~\cite{mohler_text_2009,mohler_learning_2011} provides CS short answers, each graded 0 to 5
by two teachers; we use their mean. \emph{SemEval-2013 Task~7}~\cite{dzikovska_semeval_2013}
(SciEntsBank and Beetle) provides science short answers labelled correct or incorrect; it is the most widely
used short-answer benchmark, and its subject checks that the short-answer findings are not specific to CS. We
use a fixed-seed random sample of 800 of its answers, from all its subsets, with every reference answer a
question has.
\emph{Rubric Is All You Need} (RIAYN)~\cite{pathak_rubric_2025} provides submissions on data structures and
algorithms to a practice website. We use 149 of its 150 submissions (one lacks a grade): 148 in Java and one in
Python. Each question has its own rubric, which marks each step of one or more accepted solution paths, and two
graders scored each submission in consensus.

\emph{PT-CS} consists of 97 complete Java exams in Portuguese from a course at Iscte, with 634 answers.
Each question has its own rubric and no reference solution. Two of the authors, who taught the course,
manually graded 379 of these answers (295 code answers and 84 short answers on theory) before this study was
designed, as a joint decision with no per-teacher record; these are PT-CS's human grades. The other answers were
not graded by the teachers and have no grade. They are graded by the models only where complete exams are needed,
in whole-exam grading and the conversation sub-study. Agreement is measured on the 379 graded answers alone, and
the conversation sub-study compares the models' grades between its conditions, which needs no human grade.

\subsection{Grading Harness}
\label{sec:harness}

A single grading harness, the software that runs every model through one common interface and records its
output, drives the whole study. Its prompt templates are written in English for every dataset, while the PT-CS
questions, rubrics, and answers stay in Portuguese, and all of them ask for the score as a JSON object. A
deterministic parser extracts the grade; unparseable output is logged and left out of the metrics (without
reasoning, at most 0.6\% of any configuration's outputs). The supplementary material gives every prompt
template, the models' identifiers and prices, the unparseable outputs per model, and the values behind every
figure.

With reasoning off, every model grades every answer of every dataset $k=5$ times, with two exceptions in the
follow-up experiment: Claude Sonnet 4.6 grades a fixed random 800 of the 2273 Mohler answers, and GLM-5.1 graded
the partial-credit prompt only on the code sets. Reasoning on, the most expensive setting, grades fixed random
samples, also $k=5$ times (Table~\ref{tab:datasets}): all 149 RIAYN answers and 32 to 175 answers on the other sets. Whole-exam
grading covers the 88 exams that contain at least one of the 295 PT-CS code answers (one to six questions each),
and the conversation sub-study grades the 97 exams, in both orders, with Qwen3.5, DeepSeek-V4-Flash, and
GLM-5.1.

\subsection{Metrics and Statistics}
\label{sec:metrics}

Every grade, the teacher's and the model's, is divided by the question's maximum mark (5 points on Mohler, 1 on
SemEval, 4 to 12 on RIAYN, and 1 to 12 on PT-CS), so all grades lie between 0 and 1. A model score below zero,
which arose when the model applied only a rubric's penalty, is set to zero.

Agreement is reported as quadratic weighted kappa (QWK), the standard measure for ordinal scoring: it penalises
large disagreements more than small ones and reaches 1 at perfect agreement and 0 at chance; all the values we
report are positive. QWK needs discrete grades, so we average each answer's $k$ grades, round the mean to the
nearest of six ordered levels (0 to 5, the points of a Mohler question; a value exactly halfway goes to the even
level), and compute QWK on these levels. The same six levels on every dataset keep the values comparable; five
or seven levels change no baseline QWK by more than 0.06.

Consistency is the mean within-answer standard deviation across the $k$ repetitions (SD$_k$); it needs no human
grade, and a lower value means more reproducible grading. The token cost of reasoning is the ratio of output
tokens with reasoning on to those with reasoning off, within each model. Costs in euros come from each call's
logged tokens at the providers' standard rates, ignoring discounts for cached input or batched requests, so they
are an upper bound; at these rates all the experiments together cost \euro{}261.7. Rank correlations use
Spearman's $\rho$. On SemEval we also turn the model's score into a correct or incorrect label at a fixed cutoff
of 0.5 and report accuracy. We do not split SemEval into its seen and unseen subsets, which were defined relative
to the training set of supervised systems; our prompted models have none.

Every contrast compares two configurations on the same answers, $N$ of them. A reasoning run that reached the
output limit without returning a grade takes the grade the same model gave that answer with reasoning off, to
keep these hard answers in the comparison, as a grading system would retry with a cheaper call. The scope
contrast uses the 295 PT-CS code answers graded within whole exams.

We report each difference with a 95\% confidence interval (CI) from 10,000 bootstrap resamples: the answers are
drawn again at random, with replacement, 10,000 times, the difference is recomputed on each draw, and the CI
spans the middle 95\% of the results. A difference is significant when its interval excludes zero; its p-value,
used by Holm's correction below, is twice the share of draws in which the difference falls on the other side of
zero. Two checks in the supplementary material repeat every comparison in other ways: drawing whole questions
instead of answers, because answers to the same question tend to resemble each other, and computing QWK on each
single run instead of on the mean of the $k$ grades. Within each group of
related comparisons (reasoning, guidance, prompt, scope, and decomposition) we also apply Holm's correction, which
keeps the chance of any false positive in the group at 5\%. Where equivalence matters, we test it with the two
one-sided tests procedure (TOST): two settings count as equivalent when the 90\% CI of their difference lies
within $\pm0.05$ QWK, a margin we fixed in advance, in the project's internal record, as too small to change any
recommendation. The conversation sub-study's intervals resample
whole exams, because the answers of one exam, graded in one conversation, are not independent.

The first part was the first and simplest attempt: it replaces the strict prompt with the partial-credit
prompt, which tells the model to give marks for whatever the answer gets right. All five models graded the two
code sets of the study both ways. Four of them, all but GLM-5.1, also graded the short-answer sets both ways,
to check that the request does no harm there. Qwen3.5 and DeepSeek-V4-Flash also graded the code sets with partial
credit and a justification of at most two sentences, written before the score.

The second part uses prompt engineering aimed at the cause of the zeros. We took every zero that Qwen3.5 and
DeepSeek-V4-Flash gave, in the runs with a justification, to an answer that the human graders had credited with at
least 20\% of its marks. We read the justification behind each of these zeros and noted the reasons it gave. We then wrote five candidate prompts, A to E in
Fig.~\ref{fig:promptexp}. Prompt A tells the grader to judge each rubric item on its own: an item earns its marks
when the answer achieves what it asks for, even with another approach, other names, or code that would not
compile, and part of its marks when the answer achieves part of it. Prompts B to E each add one technique to A,
aimed at one of the reasons. Qwen3.5 and DeepSeek-V4-Flash graded the PT-CS code and RIAYN answers with each
candidate and, for comparison, with the partial-credit prompt again at the same time. A second round merged the two
candidates that helped most in the first round, those with the highest mean agreement, into a new prompt, the
code prompt. Finally, all five models used the code prompt to grade every set of the study that has a rubric.

The prompts and the sets of each step were fixed in the project's internal record before its runs. Which prompt
the guide uses for each type of answer was decided after seeing the results. The supplementary material gives every
prompt verbatim.

\subsection{Configuration Guide Validation}
\label{sec:validmethod}

We first tested the configuration guide with the answers it was built from, and then added two validation

short answers on communication networks. Two trained annotators scored each answer in consensus, with partial
credit, and each question has a reference answer. We use a fixed-seed random sample of 300 of its 2981
answers~\cite{saf_release_2022}, covering all 31 questions. \emph{HARMOGEN-R}~\cite{mendonca_harmogenr_2026}
provides C++ code answers from a data-structures course, in Portuguese. Four instructors graded each answer
independently and blind, with one rubric per question that they wrote themselves, made of separately scored
criteria. The models receive this rubric; the dataset's rubrics written by LLMs are not used. We use all 129
non-empty answers to its three code questions, with the instructors' mean as the human grade.

On both datasets, each model graded every answer three times with the guide, with the baseline configuration,
and with reasoning on, which was graded with the partial-credit prompt and, on SAF, only on the first 150 of the 300
answers, in their fixed random order. As in the main comparison, a reasoning run that returned no grade takes the
grade the same model gave that answer with reasoning off. Before any of these answers was graded, we fixed, in the
same internal record, the criterion the guide had to meet: on each dataset and with every model, the guide had to
agree with the human grades at least as well as every alternative without reasoning, so that no alternative agreed
significantly better. Besides the baseline, these alternatives were no guidance and, on code, a score per criterion
(with the code prompt) and the partial-credit prompt. Claude Sonnet 4.6 graded only with reasoning off and one
holistic score, as in the study.
